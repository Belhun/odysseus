## Title/topic

Read-only invoice viewer gets a top **Edit** button; post-save navigation returns to the screen that opened the invoice flow (project view vs client dashboard) instead of always landing on the client dashboard.

## Features

- **Viewer Edit control:** `InvoiceViewerView.axaml` header (`Grid` `*,Auto`) — title + "Read-only view" left; **Edit** button right bound to `EditInvoiceCommand`. Footer "This view is read-only." removed; row defs become `Auto,Auto,*`.
- **`InvoiceViewerViewModel.EditInvoiceCommand`:** `[RelayCommand(CanExecute = CanEditInvoice)]` → `NavigationService.NavigateToInvoiceCalculatorEditAsync(Invoice.Id)`; disabled until `Invoice` is loaded (`NotifyCanExecuteChanged` on invoice set). Same edit path as client dashboard edit.
- **Return-context model:** new `SysForge/Models/InvoiceNavigationReturnContext.cs` with `ViewModelType`, optional `ClientId` / `ProjectId` / `WorkOrderId`.
- **Capture on invoice-flow entry** (`NavigationService.CaptureInvoiceReturnContextIfStartingFlow`): called from `NavigateToInvoiceViewerAsync`, `NavigateToInvoiceCalculatorEditAsync`, `NavigateToInvoiceEditAsync`, `NavigateToInvoiceCalculatorWithClientAsync`. Opening Edit from the viewer does not overwrite an existing context.
- **Post-save return:** `InvoiceCalculatorViewModel` save success calls `NavigateAfterInvoiceSaveAsync(savedClientId)` instead of `NavigateToClientDashboardAsync`. Service trims invoice screens from history (`TrimInvoiceFlowFromHistory`) then restores the recorded screen.
- **Origins supported (as stated in chat):** `ProjectDetailFourColumnViewModel` (new layout), `ProjectDetailViewModel`, client dashboard variants (`ClientDashboardViewModel`, `ClientDashboardWireframeClassicViewModel`, `ClientDashboardWireframeViewModel`), `WorkOrderDetailViewModel`, projects hub; fallback to client dashboard when no context (e.g. sidebar).
- **Project restore:** `ProjectDetailFourColumnViewModel.PrepareForReturnNavigation(int projectId)` restores picker/`SetProjectId`/selection flags when returning from invoice viewer or calculator.
- **Save-as-new path:** `NavigateToInvoiceViewerAfterSaveAsNewAsync` uses `TrimInvoiceFlowFromHistory` and no longer forces dashboard load before the viewer (back uses the same return history).
- **Scoped commit files:** `InvoiceNavigationReturnContext.cs`, `NavigationService.cs`, `InvoiceCalculatorViewModel.cs`, `InvoiceViewerViewModel.cs`, `InvoiceViewerView.axaml`, `ProjectDetailFourColumnViewModel.cs`. Unrelated tree work (screw maps, plans) left uncommitted.
