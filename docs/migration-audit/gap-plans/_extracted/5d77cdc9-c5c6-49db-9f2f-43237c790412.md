## Issues/bugs

No user-reported product defect. Build/tooling fixes during implementation:

- **AVLN / XAML compile:** `SelectInvoiceDialog` / `SelectInvoiceDeviceDialog` needed `xmlns:models` + `DataTemplate DataType="models:Invoice"` / `InvoiceDevice` after first `dotnet build` failure.
- **Dialog ctors:** removed broken parameterless/`null!` constructors; ensured `InitializeComponent()` runs in the DI-facing constructors.
- **Behavior gaps framed as product risks (not crashes):**
  - Create path fails with toast if work order missing (acceptance only obvious in Invoice Calculator).
  - `CreateProjectFromInvoiceService` reads DB device rows only; unsaved in-memory calculator devices yield *"No device on invoice"* (calculator path saves devices before create; new path does not).
  - Setup dialog shows **all** invoice line items, not filtered per device (plan wants per-device lines).
  - Dual UIs after create: calculator → classic detail; new buttons → four-column.
  - Projects hub **"Accepted — missing projects"** rows only open the invoice; no create button.

## UX

- Header CTA on four-column project shell for discoverability when browsing projects.
- Dashboard path is context-aware: selected preview invoice skips the invoice picker.
- Multi-step dialogs: choose invoice → (maybe) choose device → setup (device ID pre-filled by `ProjectService.GenerateDeviceId()`, category required, parts default all checked).
- Guardrail toasts instead of silent failure when WO missing, no devices, or every device already has a project.
- Projects are **never auto-created**; one explicit create per device (aligned with `Plans/Feature-Plans/Projects-and-Work-Orders-Plan.md`).
- Agent left flow polish for a follow-up discussion after buttons shipped.
