## Title/topic

Client Dashboard invoice **View** / **Edit** buttons fail to switch the shell view; follow-on regression where home **Dashboard** cards no longer open **Client Dashboard**; root-cause analysis of duplicate `CurrentView` writes; Cursor rule `state-and-event-lifecycle.mdc`.

## Features

- **Client Dashboard → View invoice:** click should open a **read-only** invoice view of the selected invoice (`InvoiceViewer` / read-only surface).
- **Client Dashboard → Edit invoice:** click should (1) load that invoice into **Invoice Calculator** and (2) **navigate** the shell to the calculator (not only mutate calculator state).
- **`NavigationService.ViewChanged`:** service raises view-changed after resolving a control so callers that use `NavigateToAsync` without going through sidebar `NavigateToItem` still update the shell (`MainWindowViewModel.ApplyNavigationResult` sets `CurrentView`, title, back state on UI thread).
- **Dashboard card → Client Dashboard:** `DashboardViewModel.CardClicked` → `MainWindowViewModel.OnDashboardCardClicked` must keep working after navigation fixes.
- **Agent rule (SysForge):** `.cursor/rules/state-and-event-lifecycle.mdc` (`alwaysApply: true`) documents duplicate-write + subscription teardown; extendable for similar lifecycle bugs.

## Issues/bugs

1. **View button no-op (visible):** Client Dashboard View click did not change what the user saw (read-only invoice view missing or navigation not applied). Exact file-level View fix lives in absent subagent `bb652a8e`; parent only confirms “View/Edit navigation fix” landed and build green.
2. **Edit button partial failure:** Invoice Calculator **did** populate with the chosen invoice, but the shell **did not navigate** to the calculator until the user switched tabs manually. Root pattern: state update worked; view swap did not.
3. **Regression after ViewChanged:** After wiring `ViewChanged` → `CurrentView`, home Dashboard cards stopped opening Client Dashboard.
   - **Mechanism:** `ViewChanged` assigns `CurrentView`; then `NavigateToItemDirect` / `NavigateToItem` assigns the **same** cached control again.
   - Old `CurrentView` setter always ran `CardClicked -=` (and calculator/drafts unsubscribes) **before** `SetProperty`. On the duplicate assign, `SetProperty` returned false → no re-subscribe → `CardClicked` dead.
   - **Fix:** unsubscribe only when `!ReferenceEquals(_currentView, value)` for `DashboardView` / `InvoiceCalculatorView` / `DraftsView` handlers in `MainWindowViewModel.CurrentView`.
4. **Files in committed fix:** `SysForge/Services/NavigationService.cs`, `SysForge/ViewModels/MainWindowViewModel.cs` (message: “Fix navigation view swap and dashboard card handler lifecycle”).
5. **Run-for-test subagent:** aborted; not a product bug.

## UX

- View = read-only invoice presentation; Edit = editable calculator with that invoice loaded.
- Navigation must be immediate and visible; populating hidden calculator state alone is insufficient.
- Dashboard client cards must remain clickable after any navigation/sync change that touches shell `CurrentView` (or Odyssey router equivalent).
- Related events also lifecycle-managed in the same setter: `InvoiceCalculatorViewModel.NavigateToDraftsRequested`, `DraftsViewModel.DraftSelected`.
