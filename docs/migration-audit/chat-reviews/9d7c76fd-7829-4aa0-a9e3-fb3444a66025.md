## UX

- Draft open can feel laggy or flaky while polling for calculator `DataContext`.
- Browser-style back/forward may skip draft autosave if `NavigateToDirectAsync` is used — user can lose in-progress calculator state.
- Heavy keyboard/focus/price-restore behavior lives in Avalonia code-behind (`InvoiceCalculatorView.axaml.cs`), not bindings.
- Settings opened via service locator modal rather than the same navigation path as other screens.
- Follow-up explanation: UI shipped feature-by-feature (card clicks, draft events, delay polling, duplicate-assign special case) while DB/services kept one playbook — hence “UI layer accreted complexity faster than conventions.”
