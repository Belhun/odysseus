## Issues/bugs

- **BUG-018 (primary):** After JSON import, Diagnostics lists clients; dashboard/calculator name search does not. Import toast can still say success.
- **Root cause:** Import writes SQLite via Dapper; normal CRUD indexes through `ClientService` → `IndexClient`. Pre-fix path never refreshed Lucene.
- **Partial-fix gap (pre this chat’s harden):** rebuild only when `result.ClientsImported > 0`. Settings **Skip** re-import leaves count at 0 → **no reindex** → stale index persists (common after upgrade + re-import).
- **Restart does not heal:** `SearchService.InitializeAsync(rebuildIfMissing: true)` rebuilds only when index is **empty/missing**, not when populated but stale (`Program.cs`).
- **Phone search can mask the bug:** digit-heavy queries hit DB merge; name-only queries fail on stale Lucene → false pass/fail in manual QA.
- **Post-commit rebuild failure:** if `RebuildSearchIndexAsync` throws after DB `Commit`, outer catch must not `Rollback` a committed transaction; nested try/catch → `Success = false` + re-import message.
- **Related out-of-scope drift:** `.db` `RestoreBackup` replaces DB with no Lucene rebuild; restart still may not rebuild non-empty stale index (called out, not fixed here).

## UX

- Two surfaces, two truths: Diagnostics = DB; client search UIs = Lucene (+ phone/email). User sees “import worked” then “Maria not found.”
- Settings import uses **Skip** by default; changing default to Overwrite was rejected as wrong UX for this bug.
- **Recovery for already-broken installs:** one JSON re-import after the fix heals the index; **restart alone is not enough**.
- If rebuild fails after commit: import reports failure with a clear re-import / retry message (do not pretend success while search is wrong).
- Manual QA must search **names** (`Maria`, `Chen`) on Client Dashboard **and** Invoice Calculator, then Skip re-import and search again; check log for rebuild message. Prefer not relying on phone-only checks.
