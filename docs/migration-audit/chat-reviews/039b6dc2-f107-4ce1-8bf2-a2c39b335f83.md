## Title/topic

## Features

- **Auto-save on exit edit** — `ProjectDetailFourColumnViewModel.ToggleEditDeviceAsync` calls `SaveProjectFieldsCoreAsync` when leaving edit mode (`IsEditingDevice` true → save → flip flag).
- **Shared save core** — `ProjectDetailViewModel.SaveProjectFieldsCoreAsync` calls `ProjectService.UpdateProjectAsync(Project)` then `OnPropertyChanged(nameof(Project))`.
- **Removed separate save control** — "Save device fields" button removed from `ProjectDetailFourColumnView.axaml` (already on branch in `58914c7`; this chat’s commit focused on VM behavior).
- Fields in scope: `Project.DeviceModel`, `Project.DeviceSerial`, `Project.DeviceColor` (bound TwoWay in edit TextBoxes; read-only TextBlocks outside edit).

- **Root cause 1 — no INotify on nested POCO:** `Project` is a plain model; editing `Project.DeviceSerial` (etc.) updated memory but read-only `TextBlock`s did not redraw.
- **Root cause 2 — Done editing only toggled UI:** Previous `ToggleEditDevice` only set `IsEditingDevice = !IsEditingDevice`; no DB write.
- **Symptom:** Serial (and other fields) typed in edit stayed visible when re-entering Edit Device Details, but view-only mode showed old values; even clicking Save Device Fields then Done Editing still failed to refresh the outside view.
- **Commit contamination note:** Agent reported `ProjectDetailViewModel.cs` in `c0abccd` also included unrelated in-progress screw-map work that was already dirty on disk; other unstaged repo changes were left uncommitted.
